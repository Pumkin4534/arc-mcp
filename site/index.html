01 / THE WORKFLOW

intent to evidence.

One compact ledger, alongside the environment you already use. No replacement interface or extra planning model.

01—02

Plan, then build.

Keep one to five broad, dependency-ordered outcomes. Preserve the details inside acceptance criteria. Edit with OpenCode’s native tools.

03

Record what ran.

Capture real command results against scoped source fingerprints. Missing, failed, interrupted or stale evidence blocks readiness.

04—05

Get a fresh perspective.

Two read-only native reviewers run in parallel. Both see the evidence packet, not the writer’s conversation. Finalize against current results.

03 / KNOW THE BOUNDARY

Useful evidence.
Honest limits.

Arc is a workflow aid, not a tamper-proof attestation system. The distinction stays visible in every completion result.

Read the security model ↗

Native-advisory by design

Native tools remain available. Same-user processes can modify host records. Only MCP-owned checks receive scoped macOS Seatbelt restrictions.

Your provider still matters

Arc adds no telemetry service. Local records include tasks, paths and command output; they are not automatically redacted. Remote models receive the review context you send through OpenCode.

Scoped, not absolute

Fingerprints are non-atomic and exclude ignored/generated content and symlink referents. Process-group cleanup does not guarantee termination of deliberately detached descendants.
